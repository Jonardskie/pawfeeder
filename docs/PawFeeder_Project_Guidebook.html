Complete Engineering & Student Guidebook

Automated Stray Animal Feeder (PawFeeder)

Full technical documentation covering physical hardware, GPIO wiring, dual-ESP32 firmware, closed-loop load-cell dispensing, coin & GCash OCR donation flows, cloud video relay, and the React web dashboard.

Control MCU: ESP32 Dev Module (v5.4) Camera MCU: AI Thinker ESP32-CAM Database: Firebase RTDB Relay: Node.js + Express (Render) Frontend: React 19 + Vite 8 (Vercel)

1 System Overview & Architecture

PawFeeder is an IoT-enabled automated kibble dispenser designed for stray animals. People can feed stray animals either on-site using physical coins or remotely from anywhere in the world through a web app using GCash donations while watching a live camera feed.

1. Control ESP32 (control_esp32.ino)

Reads the coin slot & HX711 bowl weight scale, drives the NEMA stepper auger with anti-clog protection, updates the 16×2 LCD, and syncs with Firebase.

2. ESP32-CAM (cam_esp32.ino)

Captures live JPEG frames, serves Local LAN HD video (1280×720), and pushes Cloud frames (1024×768) outbound over HTTPS to the Render relay.

3. Firebase RTDB + Render Relay

Firebase stores real-time telemetry, dispense commands, logs, and anti-fraud GCash receipt hashes. Render (cam-relay) relays MJPEG video globally.

4. React Web App (pawfeeder-web)

Deployed on Vercel. Displays live video (with night-light & rotate controls), verifies GCash receipts via Tesseract OCR, and provides PIN-locked Admin tools.

3 Overall System Functions & Operational Flows

A. Pricing & Portion Tiers

Both the Coin Slot and the Web Donation UI share the exact same peso-to-gram tiers:

Donation / CoinTarget FoodCoin Pulses Accepted (parseCoinBurst)
₱1050 g8 – 13 pulses
₱30150 g27 – 33 pulses (e.g. ₱20 + ₱10)
₱50250 g47 – 53 pulses
₱70350 g67 – 73 pulses
₱90450 g87 – 96 pulses

B. On-Site Coin Feeding Workflow

  1. Noise-Filtered Interrupt: coinInterrupt() measures LOW pulse width on GPIO 18. Spikes shorter than 2ms or longer than 150ms are ignored.
  2. Burst Snapping: After 650ms of silence (COIN_SILENCE_MS), parseCoinBurst() snaps the pulse count to the nearest valid ₱10–₱90 value and adds it to balancePhp and NVS flash (total_php).
  3. Tier Wait / Auto-Dispense: If balancePhp == 90, it dispenses immediately. For lower tiers (₱10, ₱30, ₱50, ₱70), it waits 3 seconds (TIER_WAIT_MS) in case the user inserts more coins, showing a countdown on the LCD. Unclaimed partial balances expire after 2 minutes (120,000ms).

C. Closed-Loop Weight Dispensing & Anti-Clog

  1. Start Snapshot: Records weightBefore using 3-sample median filtering and sets Firebase dispensing: true.
  2. Chunked Auger Push: Runs the stepper in 650ms forward chunks (RUN_CHUNK_MS) with a soft-start torque ramp (70ms). Every 4 chunks, it performs a 45ms reverse "peck" (MICRO_BACK_MS) to prevent kibble wedging.
  3. Jam Detection & Unjamming: Between chunks, readCleanWeight() checks if bowl weight increased by at least 1.5g (MIN_PROGRESS_G). If weight stalls for 4 consecutive chunks (STALL_CHUNKS_LIMIT), unjamAuger() runs: 450ms slow reverse → 4× rapid forward/reverse shake cycles → 350ms high-torque forward push.
  4. Completion: Once bowlWeight >= weightBefore + targetGrams, the motor stops, updates food_level_pct, logs event/last_dispense, and sets dispensing: false.

D. Online GCash Donation & OCR Verification Flow

  1. User picks a tier (₱10–₱90) in DonationCard.jsx and clicks Feed, opening GCashModal.jsx.
  2. User scans the GCash QR (JONARD S. | 09535497843) and uploads the receipt screenshot.
  3. receiptVerifier.js runs Tesseract.js OCR in the browser, extracts & validates the 13-digit GCash Reference Number, checks receiver details/amount, and computes a SHA-256 hash of the image so the same screenshot can never be reused.
  4. If valid, the web app writes /feeder/unit001/cmd/dispense = { active: true, grams } to Firebase. The Control ESP32 polls every 2s, dispenses the food, and streams live dispensed_g progress back to the modal.

4 Firmware Deep-Dive & Flashing Guide

Required Arduino IDE Libraries

  • Control ESP32: LiquidCrystal_I2C, WiFiManager (by tzapu), HX711 (by Bogdan Necula), plus built-in ESP32 WiFi, WiFiClientSecure, HTTPClient, Preferences, Wire.
  • ESP32-CAM: Built-in esp_camera (Board: AI Thinker ESP32-CAM), WiFiManager, WiFi, WiFiClientSecure, HTTPClient.

How to Flash the ESP32-CAM

  1. Connect FTDI/USB programmer: TX → U0RXD, RX → U0TXD, GND → GND, 5V → 5V.
  2. Bridge IO0 → GND with a jumper wire before powering on (Serial Monitor will show waiting for download).
  3. Close Serial Monitor in Arduino IDE, select Board AI Thinker ESP32-CAM, and click Upload.
  4. After 100% upload completes, remove the IO0 → GND jumper and press RST.

How WiFiManager Works on Both Boards

Important Behavior: 2-Minute Boot Window Only WiFiManager runs only once at startup (setup()). If a board is powered on out of range for a long time, its 120-second portal closes. Always unplug & re-plug the machine when moving to a new Wi-Fi location.
  • Control ESP32: Tries last saved Wi-Fi for 20s → opens hotspot PawFeeder-Setup (password pawfeeder123) for 120s → falls back to WiFi Offline / Coin Mode Only if unconfigured.
  • ESP32-CAM: Tries hardcoded WIFI_SSID ("MPT MAUI STATION") for 20s → tries saved WiFiManager for 20s → opens PawFeeder-CAM-Setup (password pawfeeder123, portal http://192.168.4.1) for 120s → restarts if timed out.

Dual-Profile Video Streaming (cam_esp32.ino)

  • Cloud Relay Mode (default): FRAMESIZE_XGA (1024×768) at jpeg_quality = 13. Pushes frames as fast as the network allows when activeViewers > 0, or 1 keep-alive frame every 5000ms when idle.
  • Local LAN Mode (GET /stream): Temporarily boosts sensor to FRAMESIZE_HD (1280×720) at jpeg_quality = 10 via setStreamProfile(true), then restores XGA on disconnect.

Cloud Video Relay (cam-relay/server.js on Render)

Home routers block inbound connections from the internet. Instead of port forwarding, the ESP32-CAM pushes frames outbound over HTTPS to https://pawfeeder-or3n.onrender.com:

EndpointMethodPurpose
/uploadPOSTReceives raw JPEG from ESP32-CAM; broadcasts to viewers (skips slow clients if writableNeedDrain); returns { ok, viewers, lamp, bytes }.
/streamGETServes multipart/x-mixed-replace; boundary=frame MJPEG stream to browsers (ignores frames ≥10s old).
/snapshotGETReturns single latest JPEG if fresher than 10s (otherwise 503).
/lampGET / POSTToggles nightLightState so ESP32-CAM turns the flash LED ON/OFF.
/GETHealth check JSON: { status, activeViewers, lastFrameAgeMs, cameraConnected }.

905Calibrate 200gMeasures a 200g reference weight, computes calibrationFactor, and saves to NVS flash.

907Hopper Refilled 100%Sets food_level_pct = 100.0.
908Reset Wi-FiCalls WiFiManager::resetSettings() and restarts ESP32 into setup portal.

How Load Cell Calibration Works

Default calibrationFactor is 944.49f. To recalibrate: (1) Empty the bowl and run Tare (904), (2) place an exact 200g reference weight on the bowl, and (3) run Calibrate 200g (905). The firmware computes: 

calibrationFactor = (medianRawReading - tareBaseline) / 200.0;
prefs.putFloat("cal_factor", calibrationFactor); // Saved permanently in NVS

8 Student Lab Troubleshooting Playbook

SymptomRoot CauseSolution
Camera init failed: 0xffffffff Uninitialized camera_config_t, loose OV2640 ribbon, or weak 3.3V power. Ensure camera_config_t config = {}; and pin_reset = -1; reseat ribbon; use 5V 2A power.
boot:0x3 (DOWNLOAD_BOOT) waiting for download IO0 is still bridged to GND. Close Serial Monitor to upload; after upload finishes, remove IO0 → GND and press RST.
Works on laptop USB, fails on wall brick Programmer board holds IO0/RST without USB host, or fast-charge brick drops 5V. Remove programmer board and power 5V/GND directly from a plain 5V 2A brick + 100–470µF cap.
PawFeeder-Setup Wi-Fi not showing WiFiManager already connected OR its 120s boot window expired. Unplug & plug back in; check phone Wi-Fi list 20–140 seconds after boot (or send Admin cmd 908).
Local LAN button blocked on Vercel Browsers block http:// camera streams inside https:// pages (Mixed Content). Use Cloud Remote on Vercel, or click Open Local Stream to open the direct LAN tab.
Cloud stream takes 30–60s on first load Render free tier cold-starting after 15 min idle, or slow home Wi-Fi upload. Wait for Render to wake and click Retry; keep ESP32-CAM within good Wi-Fi RSSI (> -75 dBm).
